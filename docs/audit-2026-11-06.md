# Application audit — November 6, 2026

Scope: WPF windows and controls, settings/credentials, conversation submission and replay, timeline state, wake word and voice lifetimes, response audio and tones, registration, updater/publisher, dependencies, existing checks and parity documentation. The current canonical rich-client protocol was read from upstream (`62bec9f121d8b6d502e9bb08c940487315e377d4`); the Android handoff supplied UX context. This is a source audit with local fixtures and rendered UI inspection, not proof of full feature parity or physical device acceptance.

## Fixed in 2026.11.6.1

| Finding | Change and evidence |
| --- | --- |
| Repeated Enter could send concurrent requests; navigation could change the conversation during a submission. | Guard submission before its first await, serialize connection/navigation, block conflicting voice/settings operations, and protect updater/idle transitions. Delayed HTTP fixture exercises repeated submission. |
| Successful sends erased text typed while waiting for HTTP. | Clear only the exact draft that was submitted. Tested with a changed draft on both success and failure. |
| Retrying an uncertain typed submission generated a new key and could execute actions twice. | Preserve the key for the same conversation/message within the running process. Handle already-restored interaction IDs without creating an orphan active request. Fixture verifies both cases. Restart durability remains open below. |
| Temporary HTTP errors permanently terminated event observation while the UI said Reconnecting. | Retry transport failures, 408, 429 and 5xx with bounded exponential delay and cancellation; consume paginated committed events before the socket subscription. Surface permanent failures with an explicit Reconnect action. Tests cover HTTP 503, 401, cancellation, socket interruption, cursor advancement and duplicates. |
| Historical audio disappeared when `tts.audio` was beyond the first page. | Read all event pages. Regression fixture places audio after event 256. |
| Retention-expired saved conversations prevented connection. | Recover a history HTTP 404 by creating and saving a new conversation. Source-reviewed and built; live retention acceptance remains pending. |
| Changing token on the same origin retained the previous owner's conversation. | Reset conversation identity/activity when either origin or token changes. Source-reviewed and built; live multi-owner acceptance remains pending. |
| Closing offline could recursively call Close inside WPF Closing and crash. | Queue the final Close on the dispatcher. Reproduced by AuditCheck before the fix; fixture subsequently exits successfully. Shutdown also cancels queued tones. |
| Conversation navigation button did nothing; buttons lacked clear disabled/pressed/focus feedback. | Wire navigation to wake the conversation, add Reconnect, restore content alignment, add state feedback and a 44-DIP button minimum. ## Remaining work, in priority order

1. **Durable draft and uncertain-request recovery.** Text retry state and voice upload/request state are still in memory. A crash/restart loses drafts and deduplication keys. Persist pending requests and drafts atomically, bind them to server/identity, and offer explicit recovery before allowing a new side-effecting retry. The current fix protects retries within one process only.
2. **Notifications and alarms.** The current upstream protocol delivers timers/reminders/announcements independently of interactions. This app registers presence but does not consume those notices. A successful timer request is not evidence that Windows will present its alarm. Add persisted handled IDs, expiry/cancellation handling, receipts, and a deliberate presentation/audio policy.
3. **Settings transactionality.** Credential Manager and JSON are written separately, and the mutable settings object changes before the file save completes. Disk-full/access failures can leave inconsistent state. A settings draft plus rollback/recovery and fault-injection tests are needed; the existing validation fix does not make the two stores atomic.
4. **Live connection status and stream lifetime.** Presence renewal is not proof that the interaction stream is healthy. Temporary stream retries currently lack distinct UI status; a late registration renewal can overwrite the connection label. Add explicit connection-state signaling and a separate conversation observer lifetime so navigation cancels abandoned streams immediately, even when no further events arrive. WebSocket retry delay is still fixed at 500 ms.
5. **Rendering performance and selection.** Each event rebuilds all message controls and timeline views. Long histories/high-frequency deltas can disrupt focus, selection and scrolling. Move toward observable view models, batched text updates and virtualization; add selectable/copyable text and safe Markdown rendering. Context/trace inspection, model-round output, attachment UI and conversation browsing remain absent.
6. **Responsive/accessibility acceptance.** The 900-DIP minimum window and fixed sidebar constrain smaller or highly scaled displays. Settings uses relatively small labels and is not fully named for screen readers. Test Narrator, keyboard-only navigation, high contrast, tablet scaling, portrait orientation and touch after responsive layout work.
7. **Audio and microphone lifecycle.** Device disconnect, permission denial, suspend/resume and physical speaker-to-follow-up-microphone timing remain unverified. WAV streaming body reads need their own bounded deadline because HttpClient's response-header timeout does not cover a stalled response body. Playback reporting failure can interrupt otherwise available audio; decouple reporting reliability from playback. Initial registration outage still requires manual reconnect.
8. **Updater hardening.** Packages remain unsigned; checksum assurance depends on trusted release metadata and transport. Verify failed-install rollback and stale seed executable behavior on the real device. Staging cleanup after failed/cancelled downloads and completed updates needs a retention policy. Existing IL3000 warning is from intentional single-file detection.

## Verification and artifacts

The native model fixture detected LIGHT UP, LOVELY CHILD and FOREVER and ignored silence. No physical microphone was used by that fixture.
